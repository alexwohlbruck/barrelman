      - content: >-
          Snaps a GPS trace to the road network and returns the path it most
          likely took,

          with elevation, distance, per-edge attributes and path details
          (road_class,

          road_environment, street_name, surface and the rest of what `/route`
          returns).


          Send JSON — `{"profile": "bike", "points": [{"lat": 35.2271, "lon":
          -80.8431, "time": "2026-05-01T10:00:00Z"}]}` —

          or a GPX document as `application/gpx+xml` with the options in the
          query string.

          `time` is optional: an ISO 8601 string or an epoch number (seconds or
          milliseconds).


          Dense and sparse traces both work. Consecutive points more than
          `max_gap_meters`

          (default 400) or `max_gap_seconds` (default 60) apart are not

          map-matched — the gap is routed instead, so a handful of photo geotags
          minutes

          apart returns in about a second rather than stalling the matcher.
          Dense runs are

          matched in parallel chunks. A stretch the matcher rejects or can't
          finish in time

          is routed through its own points, and `segments` says which parts were
          matched,

          which were routed, and why.


          `gps_accuracy` (metres, default 10, max 50) is the search radius

          around each point. Larger values tolerate noisier GPS but are much
          slower.

          `snap_prevention` (e.g. `bridge,motorway`) applies to routed
          stretches: it stops a point

          taken under an overpass from snapping onto the road above. At most
          2000 points.


          `snapped_points` gives each input point's position on the returned
          path, how

          far it moved (`offset`) and how far along the path it lies.
