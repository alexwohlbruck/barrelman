Barrelman is designed to be run by you. Every service is a published Docker image, every data source is public, and nothing calls home. This section takes you from an empty server to a running instance with imported data, an administrator account, and an API key that answers real queries.

Every step says how to tell it worked. Prefer the verification command over assuming success — most failures in this pipeline are silent and surface hours later as empty search results.

## Decide what you're running

Barrelman is two products in one codebase. Which one you want changes almost nothing about the install, but a lot about the configuration.

| | Private engine | Public metered API |
|---|---|---|
| Who calls it | Your own apps | Developers who sign up |
| Auth | One shared `BARRELMAN_API_KEY` | Per-account `brm_live_…` keys |
| Accounts | Only yours, for the console | Open sign-up |
| Billing | Off | Polar |
| Extra setup | None | SMTP, TLS, terms, Polar |

**Most self-hosters want the private engine.** With no `POLAR_ACCESS_TOKEN` the whole commercial surface is inert: every account sits on the free plan, the console hides its billing pages, and the Polar SDK is never constructed. Metering still runs, but only so you can see your own usage.

These pages build the private engine first. [Going to production](/self-hosting/production) covers what to add if you are exposing it publicly.

## Requirements

### Software

- **Docker** 24+ with **Compose v2** (`docker compose version`)
- `curl`, and enough disk for the OSM extract *plus* the database *plus* the routing graph

Nothing else. You do not need Bun, Node, Postgres, osm2pgsql or Java on the host — every tool lives in a container. A clone of the repository is optional; the install below downloads a single Compose file.

### Hardware

Sizing is driven entirely by how much geography you import.

| Scale | DB size | RAM | Disk | OSM import time |
|---|---|---|---|---|
| One US state (e.g. North Carolina) | ~10 GB | 8 GB | 60 GB | 20–40 min |
| Full United States | ~60 GB | 32 GB | 250 GB | 6–12 h |
| Europe | ~100 GB | 64 GB | 400 GB | 12–24 h |

The RAM figures assume everything runs on one box. GraphHopper loads its routing graph into JVM **heap** rather than memory-mapping it, so it wants several GB to itself, and MOTIS and Elasticsearch each want their own. Search latency is dominated by whether the database's working set stays resident, so give Postgres whatever is left.

Add roughly 1 GB of RAM and tens of GB of disk if you enable the Pelias address geocoder.

## Install

### 1. Create the directory

The directory name becomes the Compose **project name**, and some scripts resolve sibling resources by that name (the `barrelman_default` network, the `barrelman_barrelman-gtfs-data` volume). Name it `barrelman`.

```bash
sudo mkdir -p /opt/barrelman && cd /opt/barrelman
```

### 2. Download the Compose file

```bash
curl -fsSL -o docker-compose.yml \
  https://raw.githubusercontent.com/alexwohlbruck/barrelman/main/docker-compose.yml
```

All images are pre-built and published — no clone, no build step.

The Compose file `include:`s `pelias/docker-compose.yml`. If you are not using the address geocoder you can ignore this; the Pelias services sit behind profiles and never start with a plain `docker compose up`. If you want addresses later, clone the repository so that path exists.

### 3. Write `.env`

```bash
cat > .env <<'EOF'
# ── Secrets ───────────────────────────────────────────────────────────────
# Both of these MUST be changed. The Compose defaults are placeholders.
BARRELMAN_DB_PASSWORD=<a long random string>
BARRELMAN_API_KEY=brm_<a long random string>
BARRELMAN_ADMIN_KEY=brm_admin_<a different long random string>

# ── Coverage ──────────────────────────────────────────────────────────────
# Which geographies the importers pull.
REGIONS=north-carolina

# ── Engines ───────────────────────────────────────────────────────────────
# GraphHopper's heap must exceed the on-disk routing graph. Raise whenever
# REGIONS grows — an undersized heap dies before it logs its version, so the
# failure looks like a crash rather than an out-of-memory.
GRAPHHOPPER_JAVA_OPTS=-Xmx6g -Xms1g

# ── Database tuning ───────────────────────────────────────────────────────
# Compose defaults are sized for a laptop. Production should give the database
# the box: ~25% of host RAM in shared_buffers, 50-75% in effective_cache_size.
# These values suit a 32GB host.
BARRELMAN_DB_SHARED_BUFFERS=8GB
BARRELMAN_DB_CACHE_SIZE=24GB
BARRELMAN_DB_WORK_MEM=128MB
BARRELMAN_DB_MAINTENANCE_WORK_MEM=2GB
BARRELMAN_DB_MEM_LIMIT=28g
EOF
chmod 600 .env
```

Generate the secrets with something like `openssl rand -hex 32`.

<Callout type="warn" title="Three things worth understanding before you continue">
**`BARRELMAN_API_KEY` unset means the data API is open.** That is deliberate — it is how every guard in this codebase spells "local development," and a fresh clone has to be usable with no configuration. On a server, set it.

**`BARRELMAN_ADMIN_KEY` gates `/admin/*`**, which can trigger full re-imports and `DROP`/`TRUNCATE`. It falls back to `BARRELMAN_API_KEY` when unset, so leaving it blank hands console power to anyone holding a data key. Set a separate secret.

**Compose does not forward the host environment.** A variable set in `.env` but not named in the service's `environment:` block is silently absent inside the container. If you add a variable and it appears to have no effect, that is almost always why.
</Callout>

Full variable reference: [Configuration](https://github.com/alexwohlbruck/barrelman/blob/main/docs/configuration.md).
