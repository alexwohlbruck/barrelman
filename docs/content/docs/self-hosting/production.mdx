Everything so far assumed `localhost`. For a real deployment:

## Reverse proxy and TLS

Caddy auto-provisions certificates. The API listens on **5001**:

```
api.example.com {
  reverse_proxy barrelman:5001
}
```

Connect the container to Caddy's network:

```bash
docker network connect caddy_network barrelman
```

Only the API needs to be reachable from off-box. Postgres (5434), Martin (5002), GraphHopper (5003) and MOTIS (5004) already bind to `127.0.0.1`, so nothing further is needed — none of them authenticate, and exposing them would publish both the database and an unmetered copy of the tile, routing and transit APIs.

If you deliberately need one of them reachable, widen the binding with `BARRELMAN_BIND_ADDR` and put a firewall in front:

```dotenv
BARRELMAN_BIND_ADDR=0.0.0.0
```

Check what is actually listening after any change:

```bash
docker compose ps --format 'table {{.Service}}\t{{.Ports}}'
```

## Tell Barrelman its own origin

```dotenv
BARRELMAN_SERVER_ORIGIN=https://api.example.com
PUBLIC_BASE_URL=https://api.example.com
NODE_ENV=production
```

`BARRELMAN_SERVER_ORIGIN` is used in sign-in emails and as the OAuth redirect base, so it must match what a browser actually reaches. `PUBLIC_BASE_URL` is the origin `/docs` advertises as its "Production" server, so the try-it button points at the real API.

<Callout type="warn">
Set `BARRELMAN_CONSOLE_ORIGIN` **only** if you serve the console on a separate hostname. It also determines the WebAuthn relying-party ID, and changing it after passkeys exist invalidates every one of them.
</Callout>

## Count your proxy hops

```dotenv
BARRELMAN_TRUSTED_PROXY_HOPS=1
```

Every per-address rate limit depends on this, and **both mistakes are silent**. `X-Forwarded-For` is a list whose first entry the caller writes, so the address is counted in from the right, landing on the entry your own outermost proxy wrote.

| Set it to | When |
|---|---|
| `0` | Barrelman is exposed directly. `X-Forwarded-For` is ignored; the peer address is used |
| `1` (default) | One reverse proxy in front — Traefik, nginx, Caddy |
| `2` | A CDN in front of that proxy |

Too high and a caller spoofs past every per-address limit by prepending entries. Too low and every request looks like it came from your own proxy, so all of them share one bucket and legitimate traffic throttles itself.

## Email

Without SMTP, sign-in codes print to the log — fine for you, useless for anyone else.

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM=Barrelman <noreply@example.com>
```

## Closing sign-up

An instance for your own use should not accept strangers:

```dotenv
BARRELMAN_REGISTRATION_MODE=invite
```

Sign-in is then restricted to accounts an administrator created.

## Optional extras

- **OAuth sign-in** — set a provider's client ID and secret and it turns on. Register the redirect as `<BARRELMAN_SERVER_ORIGIN>/auth/oauth/<provider>/callback`. Google, GitHub and GitLab are supported.
- **Terms of service** — setting `BARRELMAN_TOS_URL` gates API-key creation on acceptance.
- **Abuse controls** — the defaults are *not calibrated against real traffic*. Read [abuse controls](https://github.com/alexwohlbruck/barrelman/blob/main/docs/abuse-controls.md) before opening sign-up.

Subscription billing is not available on a self-hosted instance — see [the note on selling access](/self-hosting#what-you-get).
